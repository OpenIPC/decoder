Компактное приложение для Android: показывает RTSP-потоки с IP-камер и декодирует H.264/H.265 аппаратно. Создано для камер с прошивкой [OpenIPC](https://openipc.org). Работает на телефонах, планшетах, телевизорах, ТВ-приставках и автомобильных устройствах.

## Возможности

- **Видео:** воспроизведение RTSP, аппаратное декодирование H.264/H.265 через MediaCodec, MJPEG по RTSP (RTP/JPEG, в одиночном режиме), автоматическое восстановление декодера, картинка вписывается в экран любой формы
- **Звук:** AAC (RFC 3640 `mpeg4-generic`, ADTS, MP4A-LATM), Opus, G.711 μ-law/A-law, L16 PCM (моно и стерео); в мультивиде — звук выбранной ячейки
- **Режимы:** одна камера или мультивид (Quad) — до 8 камер на одном экране, сеткой 2×2 или 3×3
- **Управление:** масштаб двумя пальцами, перемещение, сброс двойным касанием, пульт Android TV (Leanback)
- **Сеть:** RTSP поверх TCP или UDP (Auto переходит на TCP), RTSP multicast, приём RTP, который камера сама шлёт по UDP (unicast или multicast), авторизация Basic и Digest, RTSP keepalive, автоматическое переподключение с растущей задержкой, индикатор качества связи
- **WebUI:** встроенный браузер для веб-интерфейса камеры
- **Прочее:** 8 слотов для камер, адреса хранятся в зашифрованном виде, скриншот долгим нажатием, приём ссылок из других приложений

## Требования

- Android 5.0 (API 21) или новее
- IP-камера с RTSP или камера, которая сама отправляет RTP по UDP (OpenIPC Majestic `outgoing`), см. [Транспорты](#транспорты)
- Сервисы Google (GAPPS) **не** нужны: приложение работает и на AOSP-сборках без них. WebUI использует системный WebView, поэтому ему нужен рабочий пакет WebView (на некоторых устройствах это *Android System WebView* от Google); его отключение затрагивает только WebUI — [#15](https://github.com/OpenIPC/decoder/issues/15)

## Быстрый старт

1. Установите APK из [релиза latest](https://github.com/OpenIPC/decoder/releases/tag/latest) и запустите приложение.
2. Коснитесь экрана или нажмите **OK** на пульте, чтобы открыть меню.
3. Выберите номер камеры (**1**–**8**), нажмите **Settings** и введите адрес камеры:
   ```
   rtsp://username:password@ip_address:554/stream=0
   ```
   Под адресом можно выбрать [транспорт](#транспорты); у нового слота по умолчанию Auto (UDP с откатом на TCP).
4. Нажмите **Save**. Приложение сразу подключится и само переподключится, если поток прервётся.

## Управление

### Меню

| Пункт        | Действие                                                                                                                                                                                       |
|--------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **1**–**8**  | Переключиться на слот камеры. Цвет номера активного слота показывает качество связи: зелёный — джиттер меньше 100 мс, жёлтый — 100–300 мс, красный — больше 300 мс. Серый номер — пустой слот. |
| **U**        | Ячейка U на весь экран: камера, которая сама шлёт RTP по UDP на порт 5600                                                                                                                      |
| **D**        | Текст в углу каждой ячейки мультивида (разрешение, кодек, декодировано/получено кадр/с, ключевые кадры, статус) — или ни в одной                                             |
| **Q**        | Включить или выключить мультивид (Quad)                                                                                                                                                        |
| **S**        | Слайды: мультивид, где все камеры только на ключевых кадрах (картинка обновляется раз в интервал ключевых кадров), минимальная нагрузка на декодер; S или Q — обратно к адаптивной сетке           |
| **Settings** | Изменить адрес и транспорт активного слота (только в режиме одной камеры)                                                                                                                      |
| **WebUI**    | Открыть веб-интерфейс камеры; логин и пароль берутся из RTSP-адреса (только в режиме одной камеры)                                                                                             |
| **Exit**     | Закрыть приложение. Мелкий текст рядом — версия приложения и хеш сборки.                                                                                                                       |

### Открытие камеры из другого приложения

Приложение принимает текст через «Поделиться» (`ACTION_SEND`, `text/plain`). Если поделиться ссылкой `rtsp://` или `udp://` из другого приложения, например из OpenIPC Network, она запишется в активный слот. Необязательный параметр `transport` (`tcp`, `udp`, `auto`, `multicast`) задаёт транспорт слота:

```sh
adb shell am start -a android.intent.action.SEND -t text/plain \
  --es android.intent.extra.TEXT 'rtsp://user:pass@192.168.1.10/stream=0' \
  --es transport udp -n com.openipc.decoder/.Decoder
```

### Мультивид (Quad)

Показывает настроенные слоты сеткой 2×2, а если занят хотя бы один из слотов 5–8 — сеткой 3×3. Девятая ячейка сетки 3×3, ячейка **U**, показывает камеру, которая сама отправляет RTP по UDP на порт 5600 устройства (`udp://@:5600`, см. [слоты udp://](#слоты-udp-majestic-outgoing)); пока поток не пришёл, в ней перечислены все адреса устройства, куда его слать. Кнопка **U** в меню открывает её на весь экран. Другие порты и multicast-группы указываются в слоте адресом `udp://`. У каждой ячейки своё подключение и свой декодер, а у видеодекодера устройства постоянный бюджет: тестовая приставка AG-216, например, декодирует в полном темпе примерно два потока 1080p30. Поэтому сетка подстраивается: ячейки стартуют на ключевых кадрах, затем по приоритету (ячейка U, пока в неё идёт поток, ячейка со звуком, потом по номеру слота) переходят на все кадры, пока декодер успевает. Остальные остаются на ключевых кадрах — картинка обновляется раз в интервал между ключевыми кадрами (в тексте в углу — `key frames`, меню **D**). Предел определяется замером на каждом устройстве. Дополнительные потоки камер (substream), если они есть, позволяют показать в полном темпе больше ячеек. Ячейка сверх лимита экземпляров декодера показывает `Decoder limit: N × H.265`. Некоторые камеры допускают только одно RTSP-подключение одновременно. Долгое нажатие на ячейку включает её звук (повторное — выключает); у выбранной ячейки виден значок AUDIO, выбор запоминается. Коснитесь любой ячейки, чтобы открыть меню.

## Транспорты

У каждого слота свой транспорт: он выбирается под адресом в **Settings** (или параметром `transport` в присланной ссылке).

| Транспорт              | Как приходит видео                              | Примечание                                                                                                                                      |
|------------------------|-------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------|
| **TCP**                | RTP внутри RTSP-соединения                      | Работает везде, в том числе через NAT и межсетевые экраны                                                                                       |
| **UDP**                | RTP по UDP, пара портов на дорожку              | Меньше задержка в локальной сети. Потерянные пакеты пропускаются, а не запрашиваются заново. На TCP не переходит                                |
| **Auto** (по умолчанию) | UDP, а если UDP не работает — TCP               | Переходит на TCP, если камера отказала в UDP или видео не пришло за 3 с, и остаётся на TCP, пока слот не изменят                                |
| **Multicast**          | RTSP multicast (Android 8.0+), при отказе — TCP | Для серверов с RTSP multicast. OpenIPC Majestic и камеры XM его не поддерживают: отвечают 400 или 451, и слот играет по TCP в том же соединении |

Фактический транспорт показывается при запуске потока в одиночном режиме (`Connected • UDP • H.265 …`), на отладочной странице и в `/stats.json` (`transport`; настройка слота — `transport_mode`). После отката там будет, например, `TCP (auto)`.

### Слоты UDP (Majestic outgoing)

Слот может принимать и RTP, который камера отправляет сама, без RTSP. Для этого вместо `rtsp://` укажите адрес `udp://`:

| Адрес                               | Значение                                                                    |
|-------------------------------------|-----------------------------------------------------------------------------|
| `udp://@:5600`                      | Слушать порт 5600                                                           |
| `udp://@239.1.2.3:5600`             | Войти в multicast-группу 239.1.2.3 на порту 5600                            |
| `udp://192.168.1.10@239.1.2.3:5600` | То же, но принимать пакеты только от этого отправителя                      |
| `udp://@:5600?codec=h265&pt=97`     | Задать кодек или тип нагрузки видео, если значения по умолчанию не подходят |

Кодек определяется по типу нагрузки RTP (96 → H.264, 97 → H.265), если не задан `codec=`; смену кодека на камере приложение подхватывает на лету. Только видео. Два слота не могут слушать один и тот же порт.

На камере добавьте устройство в адресаты `outgoing` в `/etc/majestic.yaml` (затем перезапустите Majestic):

```yaml
outgoing:
  servers:
    - udp://192.168.1.20:5600
```

`/api/v1/outgoing.json` на камере показывает, идёт ли отправка. Majestic умеет слать и в multicast-группу (`udp://239.1.2.3:5600`), тогда одну камеру могут смотреть несколько устройств. В Wi‑Fi приложение держит multicast lock, пока состоит в группе.

## Отладочная страница (порт 8085)

Пока приложение работает, оно отдаёт отладочную информацию по HTTP на порту **8085** — для браузера или `curl` из той же сети:

- `http://<приставка>:8085/` — снимок на всю страницу, поверх каждой ячейки камера, размер, fps и потери (красным); в шапке версия, время приставки и аптайм;
- `http://<приставка>:8085/snapshot.jpg` (`?labels=0` — только кадры) — картинка с раскладкой экрана в разрешении экрана (не больше 1920×1080) из кадров, которые приложение показывает сейчас; ячейка без видео — чёрная с её статусом. Снимается только по запросу; страница обновляет её раз в 3, 5 или 10 с, пока вкладка видна;
- `http://<приставка>:8085/stats.json` — то же в JSON, для скриптов;
- `http://<приставка>:8085/log` — последние 500 строк лога приложения.

Отвечает только клиентам из локальной сети (loopback, 10/8, 172.16/12, 192.168/16, link-local, IPv6 fc00::/7), остальным — 403. Логины и пароли не показываются.

## Известные ограничения

> [!IMPORTANT]
> На каждый пункт заведён issue — комментарии, результаты проверок и pull request приветствуются.
>
> - **RTSP multicast требует Android 8.0+** и сервера, который его поддерживает; камеры OpenIPC его не поддерживают — [#69](https://github.com/OpenIPC/decoder/issues/69)
> - **Не поддерживаются звук G.726 и MP4A-LATM с конфигурацией внутри потока (`cpresent=1`).** OpenIPC Majestic их не использует, а камеры с G.726 обычно умеют отдавать G.711 или AAC — [#14](https://github.com/OpenIPC/decoder/issues/14)
> - **Логин и пароль передаются в открытом виде** по RTSP/HTTP без шифрования (Basic, если камера не запросила Digest); RTSPS не поддерживается и не планируется — [#16](https://github.com/OpenIPC/decoder/issues/16)
>
> Известные ошибки собраны отдельно, под [меткой `bug`](https://github.com/OpenIPC/decoder/issues?q=is%3Aissue+is%3Aopen+label%3Abug).

## Сборка

Нужны JDK 17 и Android SDK (platform 36). Путь к SDK задаётся через `ANDROID_HOME` или `android/local.properties`.

```bash
cd android
./gradlew assembleDebug        # отладочная сборка, ключи подписи не нужны
# → app/build/outputs/apk/debug/app-debug.apk
```

Для релизной сборки нужно хранилище ключей `android/key.jks` и переменные окружения:

```bash
export KEYSTORE_PASS=your_password
export KEY_ALIAS=your_alias
export KEY_PASS=your_key_password
./gradlew assembleRelease      # → app/build/outputs/apk/release/app-release.apk
```

Отладочная и релизная сборки подписаны разными ключами. Чтобы перейти с одной на другую, сначала удалите приложение; сохранённые адреса камер удалятся вместе с ним.

**CI:** GitHub Actions собирает каждый push. Push в `v2` и `basic` обновляет релиз [latest](https://github.com/OpenIPC/decoder/releases/tag/latest) и отправляет уведомление в Telegram-канал OpenIPC. Для остальных веток APK прикладывается только как артефакт на странице запуска.

## Архитектура

| Класс                                    | Назначение                                                                                                                                 |
|------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------|
| `Decoder`                                | Главная activity: интерфейс, жизненный цикл, настройки, декодирование видео одной камеры, сетка мультивида                                 |

| `RtspAuth`, `Sdp`                        | Авторизация Basic и Digest; разбор описания сессии камеры                                                                                  |
| `Transport`, `UdpReceiver`, `RtpReorder` | Согласование транспорта; приём по UDP и multicast с фильтром отправителя; восстановление порядка пакетов                                   |

| `NalAssembler`                           | Сборка NAL-блоков H.264/H.265 из RTP-пакетов, отбрасывание блоков, повреждённых потерями                                                   |
| `MediaCodecManager`, `DecoderRetry`      | Жизненный цикл аппаратного видеодекодера и восстановление после ошибок                                                                     |
| `AudioManager`, `AudioConfig`            | Звук: преобразование G.711/L16, декодирование AAC/Opus, вывод через AudioTrack                                                             |
| `QuadCell`                               | Одна ячейка мультивида: своя сессия, декодер и звук по выбору                                                                              |
| `MenuManager`                            | Всплывающее меню, редактор адреса, браузер WebUI                                                                                           |
| `CredentialStore`, `KeystoreCipher`      | Зашифрованное хранение адресов камер (Android Keystore)                                                                                    |
| `FramePool`, `Frame`                     | Пул буферов, снижает нагрузку на сборщик мусора                                                                                            |
| `App`, `Crash`                           | Обработчик необработанных исключений и экран отчёта о сбое                                                                                 |
| `DebugServer`, `NetInfo`                 | Отладочная страница на порту 8085 (только локальная сеть), адреса устройства                                                               |

Сеть, декодирование видео и звук работают в отдельных потоках, поэтому медленный декодер не блокирует сокет.

## Безопасность

- Логин и пароль берутся из адреса и передаются в заголовке `Authorization`: сначала Basic, Digest — если камера его запросит. В строку RTSP-запроса они не попадают.
- RTSP, RTP по UDP и HTTP без шифрования, RTSPS не поддерживается. Если камера ждёт логин и пароль прямо в пути или параметрах адреса (например, `user=…_password=…`), они уходят с каждым запросом. Используйте приложение только в доверенных сетях, см. [#16](https://github.com/OpenIPC/decoder/issues/16).
- Адреса камер вместе с паролями хранятся в закрытом хранилище приложения в зашифрованном виде (AES-256-GCM, ключ в Android Keystore, Android 6.0+). На Android 5.x или если Keystore недоступен — в открытом виде. Резервное копирование отключено (`allowBackup="false"`).
- Отладочная страница на порту 8085 без шифрования и пароля; она отвечает только клиентам из локальной сети и не показывает логины и пароли.
